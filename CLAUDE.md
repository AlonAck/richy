# CLAUDE.md

Guidance for Claude Code (and other AI assistants) working in this repository.

## What Richy is

Richy is a personal budgeting PWA (web + iOS via Capacitor) built as a single
giant React component, `budget-app.jsx` (~29k lines), backed by Firebase
(Auth + Firestore) and a handful of Vercel serverless functions in `api/`.
The flagship AI feature is **Richard**, a chat-based financial advisor proxied
through `api/chat.js` to the Anthropic API.

There is no bundler-based dev server and no test suite. Read `budget-app.jsx`
directly for behavior — it is the single source of truth for the UI.

## Build & dev workflow

**There is no `npm run dev`.** Local development uses `preview.html`, which:
1. Loads React, ReactDOM, and Firebase compat SDKs via plain `<script>` tags.
2. Fetches `budget-app.jsx` as text, strips `import` lines, and runs it through
   `Babel.transform` (JSX → `React.createElement`) **in the browser, at load
   time**.
3. `eval()`s the result and mounts `App`.

This means: **just open/serve `preview.html` and edit `budget-app.jsx`
directly** — no compile step, no watcher, refresh the page to see changes.

Production (`npm run build` → `node build.mjs`, invoked by Vercel via
`vercel.json`'s `buildCommand`) does the equivalent transform once, ahead of
time, with real Babel (`@babel/core` + `@babel/preset-react`), and writes the
result to `public/dist/app.js`. It also:
- Copies static files (`index.html`, `sw.js`, fonts, badges, legal pages) into
  `public/`, stamping a `BUILD_ID` into `index.html`/`sw.js` for cache-busting.
- Vendors React/Firebase from `node_modules` into `public/vendor/` — **never**
  reintroduce CDN `<script src="https://unpkg.com/...">` tags for these; they
  broke cold boots on iOS/Capacitor where the service worker can't run (see
  the long comment block in `build.mjs` for the full history).

**Golden rule when editing `budget-app.jsx`:** whatever you write must satisfy
*both* the runtime-Babel pipeline (`preview.html`) and the ahead-of-time Babel
pipeline (`build.mjs`) — both use the same `@babel/preset-react` transform, so
in practice this just means: stick to plain JSX + ES features Babel handles,
keep the `export default function App` shape (both harnesses strip/rewrite
that line), and don't rely on Node-only or bundler-only syntax (no `import()`,
no path aliases, no `.jsx`/`.ts` extension resolution beyond what's already
wired).

The `RC` shim in `build.mjs`'s preamble is a **minimal Recharts stand-in**
(just enough `PieChart`/`Pie`/`Cell`/`ResponsiveContainer` to render the one
donut chart in the app) — it is not the real `recharts` package. If you need
more chart functionality, either extend this shim in both `build.mjs` and
`preview.html` (they must stay in sync) or reconsider whether a real charting
dependency is worth the added build complexity.

## Serverless API (`api/`)

Each file is a standalone Vercel Node function (CommonJS, `module.exports`).
Recurring conventions — follow them for any new endpoint:
- **Auth**: verify a Firebase ID token (`Authorization: Bearer <token>`) via
  `firebase-admin`, except for endpoints that are intentionally public
  (`waitlist.js`) or use their own token (`bank-sync.js`'s per-user sync key).
- **`initAdmin()`**: every file re-implements the same lazy, idempotent
  `firebase-admin` init from `FIREBASE_SERVICE_ACCOUNT` (raw or base64 JSON).
  Keep new endpoints consistent with this pattern rather than centralizing it
  differently, unless you also update every existing caller.
- **CORS**: reflect only trusted origins — production domain, Vercel preview
  URLs (`https://richy-*.vercel.app`), and localhost. Copy the `corsOrigin()`
  pattern rather than `Access-Control-Allow-Origin: *`.
- **Data boundary**: the running app owns `users/{uid}` and overwrites it
  wholesale via `.set()` (not merge) — server endpoints must **never** write
  directly into `users/{uid}`; they write into subcollections
  (`users/{uid}/syncInbox`) or server-only top-level collections
  (`leumiFinteka/{uid}`, `syncKeys/{key}`) that aren't listed in
  `firestore.rules` and are therefore deny-all to clients.
- Rate limiting where present (`chat.js`) is in-memory/best-effort per warm
  instance, not a hard guarantee — don't assume it survives cold starts or
  multiple instances.

## Firestore rules

`firestore.rules` is the actual authorization boundary — not obscurity, not
the API layer. Any new client-writable data shape needs an explicit rule;
anything not listed is deny-all by default, which is deliberately relied upon
for server-only collections (see above).

## Design system status

There are **two, not-yet-unified** design systems:
1. `budget-app.jsx`'s own inline tokens (`T` object, `THEMES.purple` /
   `.classic` / others) — this is what's actually live in the shipped app
   today, including the multi-theme (palette-switching) support.
2. `design-system/` — a separate npm package with its own primitives and
   tokens, and `components/ui` + `lib/utils.ts` — a shadcn/ui-style TSX
   component set. Neither is currently imported by `budget-app.jsx`.

Don't assume changes to `design-system/` or `components/ui` affect the running
app. If asked to change the app's visual appearance, edit `budget-app.jsx`'s
`T`/`THEMES` tokens and inline styles directly unless told otherwise.

## Localization

The app supports multiple languages including Hebrew and Arabic (RTL). When
touching user-facing strings, check for existing locale plumbing in
`budget-app.jsx` before adding new hardcoded English text.

## Conventions worth preserving

- Comments in this codebase tend to explain **why**, especially around
  non-obvious constraints (App Store guidelines, iOS/Capacitor quirks, cache
  invalidation, security tradeoffs). Match that style — don't strip these
  comments and don't add comments that just restate the code.
- Vanilla-JS-flavored patterns show up deliberately in places that run through
  `eval()`/Babel-only transforms (e.g. `var` instead of `let`/`const`, no
  `"use strict"` in the compiled bundle) — don't "modernize" this without
  checking it survives both build pipelines.
- Prefer editing `budget-app.jsx` in place over introducing new files/modules;
  the whole app intentionally stays as one component tree so the no-bundler
  dev loop keeps working.
