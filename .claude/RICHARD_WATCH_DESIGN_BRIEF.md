# Richard Watch — brief for Design

The engine is built. No screens were designed — that is this document's job to
hand over.

Today "Spotted Leaks" is one card that looks backwards: it audits past
transactions and lists waste. Richard Watch is the layer above it that runs
continuously and answers a different question — *what is about to go wrong, and
what closes it*. Nine new detectors, a 30-day forecast, a daily digest, and the
piece that makes Richard an advisor rather than a dashboard: when a goal is
behind, the engine names the exact subscriptions to cancel that close the gap.

Everything below already computes and is covered by scenario tests. Nothing here
needs new backend work.

## 0. The one rule that governs every number

Every figure is derived from the user's own transactions, budgets and goals.
Nothing is generated by the model — Richard only *narrates* finished numbers and
*drafts letters*. Any screen may quote any figure the engine emits verbatim.

Three kinds of money, and they must never be added together on screen:

| Field | Means | Safe to show as |
|---|---|---|
| `monthly` | keeps leaving every month until something changes | "…/mo", "…/yr" |
| `oneOff` | a single amount to claim back (double charge, refundable fee) | "…to claim back" |
| `observed` | already spent, nothing will bring it back (a category that jumped) | "…this month" |

A row with `subsumed: true` is real and worth showing, but its money is already
counted by another row — never include it in a total. (This mattered: before the
fix the headline figure double-counted a price rise inside its own subscription,
and rent was being reported as "recoverable".)

## 1. Colour — how this stays Cornflower Ocean for free

The engine never emits a hex value. Every signal carries a **token name** in
`tint`, resolved through `T` at render time, so the same component is correct in
all three palettes and in both light and dark without Design maintaining a second
set of specs.

| `tint` | Cornflower Ocean, light | Cornflower Ocean, dark |
|---|---|---|
| `orange` (the primary accent) | `#3C4C82` deep navy | `#7E9BF2` light periwinkle |
| `red` | `#E03030` | `#EF4A44` |
| `gold` | `#C8983A` | `#E8B44C` |
| `green` | `#27A85F` | `#3DDC84` |
| `blue` | `#2E7DD6` | `#5AA9F0` |
| `purple` | `#9B6DB5` | `#C08FDC` |
| `btn` | periwinkle→navy gradient | lighter periwinkle gradient |

**Please design against the token names, not the hexes above** — the hexes are
there so you can see what it looks like today.

`icon` on every signal is an id that already exists in the app's `SVGIcon` set,
so no new icon work is required to ship: `refresh up credit chart shield calendar
film spark coins budgets flame goals down search`.

## 2. The signal — one shape for every row

Every detector normalises to this, so one card component can render all of them:

```js
{
  id, type, group, kind, horizon, severity,   // routing + ranking
  tint, icon,                                 // presentation tokens
  title, subtitle,                            // finished English copy
  monthly, oneOff, observed, annual, amount,  // the money (see §0)
  subsumed,                                   // true => excluded from totals
  actions,                                    // the button list, see §5
  meta                                        // full detector object for detail views
}
```

- `group` — `"leak"` (money going out) or `"risk"` (something about to break)
- `kind` — `"recover"` (get money back) / `"prevent"` (stop a loss) / `"decide"` (a choice)
- `horizon` — `"now"` / `"soon"` / `"watch"`
- `severity` — 0–100, **comparable across every type**, so one sorted list is
  meaningful. Money is scored against the user's own income (5% of a month tops
  the scale), so ₪40 is not "urgent" for everyone.

`horizon` and `severity` are the two fields worth designing around — they are
what lets one screen hold a blown budget and a forgotten subscription without
either drowning the other.

## 3. The new features

### Already wired into the existing Spotted Leaks card (no new screen needed)

These appear in the shipped list today, using the existing row component.

1. **Fee finder** (`fee`) — overdraft, late, ATM, foreign-transaction, wire and
   account fees, grouped by family. The most literal found money there is: nobody
   chooses to pay these. Richard drafts a **refund request** (new letter type).
   Only annualised when the fee has actually repeated across two or more months.
2. **Annual renewal warning** (`renewal`) — a yearly subscription about to
   auto-renew, flagged up to 45 days ahead with the exact due date. The single
   biggest "I forgot I agreed to this" charge, caught *before* it lands. Carries
   a `confidence` field — say so on screen when it is `"low"`.
3. **Overlapping services** (`overlap`) — two or more live subscriptions doing
   the same job (streaming, music, cloud, AI, fitness, news, creative tools).
   Presented as **one decision per family**, not one row per service, because
   people cancel a category, not a list. Quotes the *cheapest* one as the saving,
   so it never over-promises.
4. **Trial that converted** (`trial`) — an intro price that has since stepped up.
   Invisible to the existing hike detector, which only compares the newest charge
   to the median.
5. **Micro-drift** (`drift`) — death by a thousand cuts: many small charges in
   one category. Observed money, never quoted as recoverable.

### New surfaces Design needs to draw

6. **Budget pace** (`pace`) — "on pace to go over", raised early enough to change
   the outcome. The number that matters is `dailyAllowance` — what is left to
   spend *per day* to land under the cap — not the fact that they are over. When
   `blown: true` it already went over and there is no allowance to quote; the
   copy switches to how far over.
7. **Cash cliff** (`cliff`) — "this month ends ₪X short", counting only money
   already spent plus recurring charges still to land. Deliberately a **floor**,
   never a guess about discretionary spending, so it is not arguable.
8. **Goal at risk + the plan that fixes it** (`goalrisk`) — **the most important
   one.** A goal that will not land by its deadline at the rate actually being
   saved, plus `plan`: the specific list of things to cancel that closes the gap,
   greedy on monthly value so it is the *shortest* list, not the mathematically
   optimal one. Rent, insurance and loans are excluded from that list by design.
   This deserves its own screen — it is the whole "advisor, not tracker"
   difference in a single view.
9. **Savings slip** (`slip`) — saving materially less of each paycheck than the
   trailing average. Held back until the 10th so one early bill does not read as
   a collapse.
10. **Next 30 days** (`forecast`) — every charge the user's own history says is
    coming, with date, amount, `inDays` and `confidence`. Renders directly as a
    timeline. This is also what the cash cliff spends.
11. **Daily digest** (`buildWatchDigest`) — what changed since the user last
    looked: new, still-open, and resolved. Diffed against ids already shown, so a
    user is told about a leak **once**, not every morning until they act. This is
    the surface for a push notification, a morning card, or a weekly email —
    and the `quiet: true` state ("Nothing needs you today") matters as much as
    the busy one. Please design the quiet state properly; it is the one that
    earns trust.

## 4. Two calls, that is the whole API

```js
const watch  = richardWatch({ tx, categories, budgets, goals, savings, businesses, investing, foundMoney });
const digest = buildWatchDigest(watch, storedSeen);   // persist digest.nextSeen
```

`watch` gives you `all` (everything, severity-sorted), `leaks`, `risks`,
`forecast`, `goalPlans` and `totals`:

```
totals = { signals, recoverableAnnual, recoverableMonthly, oneOffTotal,
           riskCount, topRiskMonthly, upcomingTotal, upcomingCount, topSeverity }
```

Note `topRiskMonthly` is the **largest single risk, not the sum** — a blown food
budget, a month ending short and a goal falling behind are three readings of one
overspend, and adding them reports a number three times the real problem.

`watchPromptPayload(watch)` produces the grounded text block to hand Richard when
you want narration on any of these surfaces — same contract the Found Money intro
already uses.

## 5. Actions — the button vocabulary

`actions` on each signal is the definitive list of what can be done about it, so
a card, a notification and a digest row never disagree:

`draft_cancel` · `draft_pricematch` · `draft_feewaiver` · `mark_recovered` ·
`dismiss` · `remind_before` · `open_budget` · `open_goal` · `open_category` ·
`plan_gap` · `review_list`

Three of these already work end to end (`draft_cancel`, `draft_pricematch`,
`draft_feewaiver` all write a real letter through Richard, plus `mark_recovered`
and `dismiss`). `remind_before`, `plan_gap`, `open_*` and `review_list` are named
and routed but have no destination yet — they are waiting on the screens in §3.

## 6. Copy and localisation

Every `title` / `subtitle` is finished English built by the engine, matching how
the shipped Found Money rows already work — so a screen can ship immediately. The
one new i18n key added is `fmDraftRefund`, translated across all four languages.

The wider gap is unchanged and still open: the rest of these strings are engine
English and will need the same `tr()` treatment as the onboarding funnel before
Hebrew ships.
